Create a Codex Chat in a Fresh Worktree

A strict companion to close-worktree: start from a clean checkout with an explicit dotfile-copy manifest, handle an existing or new branch, initialize an independent Kanban database, and use native Codex worktrees from end to end.

The Decision

Add one canonical Orchestra skill named create-codex-worktree. It creates a native, user-visible Codex worktree chat. The user supplies every branch decision.

Hard Preflight: the invoking worktree must be clean and must contain .worktreeinclude at its repository root. If either condition fails, stop. Do not stash, commit, discard changes, create the file, or continue with a guess.

Preflight Is a Stop Gate

The skill resolves the current repository root and runs exactly these checks before switching a branch or creating a Codex thread:

current_root="$(git rev-parse --show-toplevel)" || exit 1
test -z "$(git -C "$current_root" status --short)" || exit 1
test -f "$current_root/.worktreeinclude" || exit 1
FailureRequired response
The current worktree has tracked, staged, or untracked changesStop and report that it must be made clean. Do not modify its state.
.worktreeinclude is absent or is anything other than a regular fileStop and report that it must be created and reviewed first. Do not create it.
Existing/new mode, branch name, or required base/parking branch was not suppliedStop and ask for the missing value. Do not choose a default.

Two Explicit Branch Paths

Existing Branch

  1. If the main checkout currently holds that branch, switch main to the user-selected parking branch.
  2. Create the Codex worktree from the existing branch.
  3. In the new worktree, run git switch <branch> so it owns the named branch.
target_branch="<existing-branch>"
parking_branch="<parking-branch>"

git -C "$current_root" show-ref --verify --quiet \
  "refs/heads/$target_branch" || exit 1
git -C "$current_root" show-ref --verify --quiet \
  "refs/heads/$parking_branch" || exit 1

if [ "$(git -C "$current_root" branch --show-current)" = "$target_branch" ]; then
  git -C "$current_root" switch "$parking_branch" || exit 1
fi

# Run inside the Codex-created worktree:
git switch "$target_branch" || exit 1

New Branch

  1. Leave or switch the main checkout to the user-selected base branch.
  2. Create the Codex worktree from that base.
  3. In the new worktree, run git switch -c <branch>.
target_branch="<new-branch>"
base_branch="<base-branch>"

git -C "$current_root" check-ref-format \
  --branch "$target_branch" || exit 1
git -C "$current_root" show-ref --verify --quiet \
  "refs/heads/$base_branch" || exit 1
if git -C "$current_root" show-ref --verify --quiet \
  "refs/heads/$target_branch"; then
  exit 1
fi

git -C "$current_root" switch "$base_branch" || exit 1

# Run inside the Codex-created worktree:
git switch -c "$target_branch" || exit 1

The user explicitly names develop, master, or another branch as the base/parking branch.

Hidden Files Use an Explicit Manifest

Use the target repository’s existing .worktreeinclude as the complete source of truth. Tracked dotfiles arrive through Git already. The manifest remains user-owned and unchanged by the skill.

# Example .worktreeinclude
.env
.env.*
fastlane/.env*
fastlane/*.json

The worktree copy follows that manifest. The skill verifies the copy and reports a failure. The manifest supplies the complete file set and credential policy.

New-Thread Bootstrap Contract

Only after preflight succeeds, the initial prompt sent to the new Codex chat performs these steps before the user’s actual task:

1. Confirm the worktree path and invoking-worktree source path.
2. Switch to the supplied existing branch, or create the supplied new branch.
3. Verify the .worktreeinclude copy; stop on failure.
4. Confirm no Kanban database/runtime was copied; stop if one exists.
5. Run "$ORCHESTRA_DIR/bin/ko-kanban".
6. Require: "Status: created kanban database".
7. Report branch, worktree path, and database path.
8. Continue with the user's requested work.
Native Codex Runtime: the Codex app owns the chat and worktree throughout the workflow.

Implementation Chunks

1 · Canonical Skill

Add AI-skills/create-codex-worktree.md with the hard preflight, two explicit branch paths, native Codex thread creation, manifest-copy verification, and Kanban bootstrap.

2 · Installed Wrapper

Run the existing global-skill installer so Codex receives orch-adhoc-create-codex-worktree. The existing installer generates the wrapper.

3 · Focused Verification

Exercise once with a new branch and once with an existing branch that initially occupies the main checkout. Verify each worktree receives the listed Fastlane files and a different, empty Kanban database.

4 · Close the Loop

Run the existing close-worktree skill on one disposable result to prove branch attachment and Kanban-history import are compatible.

Acceptance Criteria

  • A new native Codex chat opens already associated with its own worktree.
  • A dirty invoking worktree stops the workflow without stashing, committing, discarding, switching, or creating anything.
  • A missing .worktreeinclude stops the workflow and tells the user to create it; the skill does not create it.
  • The user supplies every branch-mode and branch-name input.
  • An existing branch works after the main checkout is parked on the specified integration branch.
  • A new branch is created from the explicitly supplied base.
  • Fastlane’s listed ignored files are available in the new worktree.
  • The new worktree has a newly created Kanban database with no imported tasks.
  • The main checkout’s Kanban database and runtime directory are never copied.
  • The resulting worktree is accepted by the existing close-worktree workflow.
  • Worktree creation and chat lifecycle use native Codex.
